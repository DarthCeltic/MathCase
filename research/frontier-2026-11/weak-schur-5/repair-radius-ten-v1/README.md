# Weak Schur: one saved coloring, ten changes

## The question

Can this one near-miss coloring of the numbers 1 through 208 be fixed by changing at most ten colors, so that no color contains three numbers `a < b` and `a + b`?

The saved coloring has three conflicts. Z3 reported `unsat` for the exact ten-change query: this particular arrangement cannot be repaired within ten recolorings in the encoded search. The query has 1,040 Boolean variables and covers all 10,712 allowed triples.

## What this result does not say

This is one solver result about one starting arrangement. It is not an independently checked proof certificate. It does not rule out another arrangement of the numbers 1 through 208, establish that 208 is impossible, or change a known Weak Schur bound. A separate lower-bound certificate is outside this package and is not needed to interpret this run.

## Reproduce the artifact audit

With Python 3.10 or later:

```text
python verify_public_artifact.py
```

This checks the 208-color input, lists its three conflicts, reconstructs the exact SMT query, compares its hash, counts all 10,712 triples and 53,769 assertions, and checks a deliberately damaged coloring. It does not call a solver.

## Replay the recorded query

The recorded run used Z3 5.3.1, one CPU, a 2 GiB memory limit, no network, and a 55-second solver limit. The exact query is `check-at-most-ten.smt2`. If Z3 5.3.1 is installed locally, the one-line check is:

```text
z3 -T:55 check-at-most-ten.smt2
```

For the recorded local isolated image, run:

```text
python run_repair_query.py --docker-image mathcase-smt-isolated:5.3.1.0 --out path/to/new-empty-run-folder
```

The image must already be present and have ID `sha256:ab8946ee9bc8040f748368d6497aa4868bd2ef42f7ae5d689e35cc38f9abdc8c`; the script never pulls an image. A public, clean-room image build is not included, so this package does not yet claim exact stranger reproduction. The SMT file and input are public and can be run with another compatible Z3 installation, whose result should be recorded with its own version.

`extract-model-at-most-ten.smt2` is included for the SAT branch only. It was not used for this `unsat` result.

## Evidence

- `seed-coloring.txt` is the exact 208-entry assignment generated by MathCase's capped search; its SHA-256 is in `public-manifest.json`.
- `check-at-most-ten.smt2` is the exact check-only formula; the recorded formula SHA-256 is in the manifest.
- `formula-audit.json` reports that the original formula reconstruction and damaged-query control passed.
- `solver-stdout.txt` and `solver-stderr.txt` preserve the original solver output bytes.
- `public-run.json` is a path-free summary of the original local receipt and binds its SHA-256. It does not replace the private raw receipt.
- A fresh replay from this packaged query is recorded in `package-replay/run.json`.

This is a bounded research diagnostic, not a Lean theorem, global impossibility result, or new bound.
