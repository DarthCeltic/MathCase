# How many color classes must change to reach 208?

Fred Rowley supplied a five-color partition, and Vicenzi and colleagues used his structural information to construct a different one. Both are partitions of 1 through 207 with no same-color sum $a+b=c$ for $a<b$. We tested both seeds. **If a valid coloring of 1 through 208 exists, at least four of the five old classes must change membership on 1 through 207 in each seed, even after color names are permuted.** This is a restriction relative to two specified starting partitions. The search for an unrestricted coloring at 208 remains open.

Choose any two old classes to keep exactly as they were on 1 through 207. The integers in the three other classes may exchange colors without any bound on the number of changes. Each retained class contains two distinct old members summing to 208, so neither can take 208. The remaining three colors must therefore cover their combined old members and 208.

That gives ten choices per seed. For each choice, we assigned a Boolean variable to each free integer and color. The formula requires exactly one color for each integer and forbids a monochromatic triple for every pair of distinct addends. Ordering the three color names by first occurrence preserves an instance of every feasible solution. Each case frees between 109 and 142 integers. All 20 formulas have checked refutations. The archive verifier independently reconstructs each formula by iterating over sums and checks the clausal proof against those exact bytes.

| Free colors from a seed | Cases | Evidence |
| --- | ---: | --- |
| Two | 20 | A standard-library checker verified 536 nodes of explicit two-way branch trees. |
| Three | 20 | A solver generated 20 DRAT proofs. DRAT-trim verified each proof. An anonymous download and a separate reconstruction of every formula reproduced all 20 checks. |
| Four | 10 | Every five-second pilot ended at its wall limit. All ten choices remain unresolved by this run. |

The two-color refutations are useful for inspecting the reasoning by hand. A branch chooses the color of a free integer. Two equal colors in a forbidden triple force the third to take the opposite color. Every leaf ends in a contradiction. Swapping the two free names lets the checker fix the color of their least member.

## Replay the checks

From this folder, Python 3.10 or later can check the two-class proof trees. The first run fetches the two hash-pinned seed files. Repeated runs can use the same seed cache offline.

~~~sh
python -B check.py --input-cache ./inputs
~~~

For the three-class result, compile DRAT-trim from the revision below. Pass the executable to the archive verifier. It downloads the 4,011,470-byte ZIP on demand, checks its SHA-256, reconstructs the formulas, verifies every proof and removes the temporary download and expanded proof files. Use `--archive /path/to/proofs.zip` with a populated seed cache for a fully offline check. Use `--scratch-dir /path/to/scratch` to select the volume for temporary files.

~~~sh
git clone https://github.com/marijnheule/drat-trim.git
git -C drat-trim checkout 2e3b2dc0ecf938addbd779d42877b6ed69d9a985
cc -O2 drat-trim/drat-trim.c -o drat-trim-check
python -B verify_archive.py --checker ./drat-trim-check --input-cache ./inputs
~~~

On Windows with MinGW use `gcc -std=gnu99 -O2 -Dgetc_unlocked=getc drat-trim/drat-trim.c -o drat-trim-check.exe`. The prebuilt checker used for the recorded run and the upstream C file have separate hashes in [the receipt](three-class.json).

To generate fresh three-color proofs, install `python-sat==1.9.dev25` in an isolated Python environment and run the following command with a new output directory. The generator also checks a deliberately invalid proof for a satisfiable formula. The two-color proof trees can be regenerated by running `search.py --input-cache ./inputs --output regenerated.json` with Python.

~~~sh
python -B recolor.py --width 3 --conflicts 75000 --seconds-per-case 120 --input-cache ./inputs --checker ./drat-trim-check --output-dir ./three-color-run
~~~

The four-free-color pilot used `--width 4 --conflicts 20000 --seconds-per-case 5`. A wall limit includes solver startup and proof checking. The receipt distinguishes an inconclusive run from a checked refutation.
